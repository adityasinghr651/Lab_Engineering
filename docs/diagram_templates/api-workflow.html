Workflow 01
User Onboarding & Session
Registration with forced member role, rate-limited login, and profile fetching.
POST 201 Created
/auth/register
Zod validates name/email/password • Bcrypt hashes password (10 rounds) • Forces role='member' • Issues JWT
Guard: Public (role parameter ignored)
→
POST 200 OK / 429
/auth/login
Sliding-window limiter checks IP (max 5 / 15m) • Compares bcrypt hash • Returns JWT token & sanitized user profile
Guard: loginLimiter (Retry-After header)
→
GET 200 OK
/auth/me
Extracts Bearer token from header • Verifies JWT signature • Returns authenticated user metadata without password hash
Guard: authenticate (Bearer Token)
Workflow 02
Project Provisioning & Scope
Create workspace containers with unique alphanumeric keys and ownership binding.
POST 201 Created / 409
/projects
Zod validates name (≥2) & key (2-10 alphanumeric) • Verifies key uniqueness • Sets owner_id = req.user.id
Guard: authenticate • Unique 23505 handler
→
GET 200 OK
/projects /:id
Queries project with relational join on users • Embeds owner object `{ id, name, email }` • 404 if missing
Guard: authenticate
→
PUT 200 OK / 403
/projects/:id
Checks ownership authorization: requesting user must be project owner or admin • Updates name/description
Guard: authenticate + Resource Authorization
Workflow 03
Issue Lifecycle & Assignment
Track issues with creator binding, optional assignees, and strict authorization gates.
POST 201 Created
/issues (or /projects/:id/issues)
Validates title (≥5), status, priority • Binds creator_id = req.user.id & optional assignee • Foreign key check
Guard: optionalAuth / authenticate
→
PUT 200 OK / 403 Forbidden
/issues/:id
Authorizes mutation: user MUST be issue creator, project owner, or admin • Transitions status: open → in-progress → closed
Guard: authenticate + Strict RBAC Check
→
DELETE 200 OK / 403
/issues/:id
Enforces creator/owner/admin authorization • Cascades deletion of all child comments in PostgreSQL
Guard: authenticate + Cascade Foreign Key
Workflow 04
Issue Discussion & Comments
Threaded conversation entries on issues with author attribution and deletion limits.
POST 201 Created / 404
/issues/:issueId/comments
Validates content (non-empty) • Checks issue existence in DB • Binds user_id = req.user.id • Returns comment
Guard: authenticate • chk_comment_content_len
→
GET 200 OK
/issues/:issueId/comments
Retrieves all comments ordered chronologically (created_at ASC) joined with author profiles `{ id, name, email }`
Guard: Public / Accessible
→
DELETE 200 OK / 403
/issues/:id/comments/:commentId
Validates comment author: only the author who wrote the comment or a platform admin can delete it
Guard: authenticate + Author/Admin RBAC
Workflow 05
Search, Filter & Pagination
Deterministic multi-column query execution with metadata envelope.
GET 200 OK
/issues?search=pool&status=open
Client specifies search term & status/priority filters • Repository injects parameterized ILIKE conditions
SQL: (title ILIKE $1 OR description ILIKE $1)
→
SORT Deterministic
&sortBy=priority&order=desc
Applies requested column sort and appends secondary tie-breaker i.id ASC to prevent pagination drift
SQL: ORDER BY i.priority DESC, i.id ASC
→
PAGINATE Envelope JSON
&limit=10&page=1
Window function COUNT(*) OVER() returns total matches • Calculates totalPages & hasMore in JSON metadata
Envelope: { data: [...], pagination: {...} }
